# 主动感知 Phase 1 设计：视觉注意力扫描（SNN 自主建立类 CNN 机制）

> 2026-11-28，衔接 brain_evolution_roadmap.md 的 Layer 1 感知层
> 用户洞察：SNN 自主建立"类 CNN 但非全图处理"的机制——每次只看主要部分，判断后再看其他部分，
> 类似眼球注意力在中心，要获得更多信息会旋转眼球。区别 CNN：非全部处理，只处理有需求的地方。
> 并串混合（视觉+其他感官并行接收，注意力串行聚焦）= 通感基础。

---

## 0. 定位与原则

**这不是"用 SNN 模仿 CNN"，而是"实现 CNN 没有的能力——注意力驱动的主动感知"。**

| | CNN | 本设计 |
|---|---|---|
| 处理范围 | 全图，被动 | 稀疏，需求驱动 |
| 计算量 | 固定 | 动态（跟随注意力） |
| 信息流 | 一次全收 | 逐窗口，时间序列 |
| 控制 | 无（前馈） | **有（扫视策略反馈）** |
| 稀疏性 | 无 | 脉冲稀疏（只处理重要） |
| 时间 | 无 | 扫视路径是时间步 |

**与现有发育式 SNN 同构**：发育式"先增殖探索、后竞争收敛"是从拓扑结构展开；本设计把同一原理
扩展到**注意力策略**——先广泛扫视（探索候选窗口），再聚焦高显著性（利用）。扫视策略学习就是
发育式原理的第二个应用面。

**规模定位**：当前 SNN 规模不大（主网络 231 神经元、视觉编码器 30 神经元），本设计**不急于实现、
不急于证明**，先把架构定清楚。SNN 构造模式本身还在摸索。

## 1. 核心概念：感受器 → 大脑第一层

用户明确定义："这里是感受器传给大脑神经网络第一层的内容。"

**现状（全图统计，无注意力）**：
```
image() → 64×64 全图 → 全局统计 {red, green, blue, bright, dark, round, square, edge, ...}
                       （9-10 维标量，无空间结构）
```
感受器把整张图压成 9 个标量，**空间结构全部丢失**。这就是"全图统计，无注意力"的现状。

**目标（窗口化，注意力驱动）**：
```
image() → 多个注意力窗口 {W0, W1, ..., Wk}，每个窗口是局部区域
          W_i → 窗口局部特征 f(W_i)（窗口内统计，非全图）
          扫视路径 [W0, W1, ..., Wk] 按时间步送进 SNN
```

**关键**：窗口不是固定网格（CNN 感受野），而是**注意力焦点**（眼球中央凹），由**扫视策略**决定
看哪里。窗口位置是**可学习的输出**，不是固定的。

## 2. 架构：注意力驱动的稀疏感知

```
                    ┌─────────────────────────────────────┐
                    │        注意力控制器 (Saccade Policy) │
                    │  学习：下个窗口看哪里                 │
                    └──────────────┬──────────────────────┘
                                   │ 扫视路径 [W0,W1,...]
                                   ▼
   感受器(图像) ──→ ┌────────────────────────────┐
                    │  窗口编码器 (Receptive Field)│
                    │  W_i → 局部特征 f(W_i)      │
                    └──────────────┬──────────────┘
                                   │ 窗口特征(局部)
                                   ▼
   时间步 t0..tn ──→ ┌────────────────────────────┐
                    │  视觉 SNN (ModalSNNEncoder)  │
                    │  逐窗口脉冲 → 概念激活       │
                    │  (输入层=窗口特征，非全图)   │
                    └──────────────┬──────────────┘
                                   │ 窗口概念激活序列
                                   ▼
                    ┌────────────────────────────┐
                    │  路径融合 (Saccade Fusion)   │
                    │  多窗口概念加权 → 全局概念   │
                    └──────────────┬──────────────┘
                                   │ ConceptVector
                                   ▼
                    ┌────────────────────────────┐
                    │  显著性估计 (Saliency)       │
                    │  下一窗口候选排序            │
                    └──────────────┬──────────────┘
                                   │ 反馈到注意力控制器
                                   ▼
```

**四层组件**：

| 组件 | 职责 | SNN 特性 |
|------|------|---------|
| **窗口编码器** | 图像 → 注意力窗口局部特征 | 局部感受野（非全图） |
| **注意力控制器** | 决定下一窗口（扫视策略） | 可学习，探索-利用平衡 |
| **视觉 SNN** | 窗口特征 → 概念激活 | 脉冲稀疏 + 时间编码 |
| **路径融合** | 多窗口概念 → 全局概念 | 序列记忆（LIF 天然） |
| **显著性估计** | 窗口"值不值得看" | 竞争胜出（winner-take-all） |

## 3. 扫视策略（可学习核心）

### 3.1 为什么可学习
CNN 感受野固定，扫视策略**不是**固定的——它由"看过什么、判断了什么"决定下一步看哪里。
这是本设计区别于 CNN 的本质：**注意力是控制回路，不是固定采样**。

### 3.2 策略学习 = 发育式原理复用
```
探索阶段：先广泛扫视（随机/显著性候选窗口），建立"窗口→概念"初步映射
利用阶段：聚焦高显著性窗口（已确认有信息的区域），压缩扫视路径
```
与 `development.py` 的"先增殖探索、后竞争收敛"完全同构——只是作用对象从**拓扑结构**变成
**注意力策略**。

### 3.3 扫视策略的状态机
```
State: 初始（无先验）
  ├─ 探索：采样候选窗口（显著性高 + 随机扰动）
  ├─ 聚焦：锁定高显著性窗口，提取局部特征
  └─ 决策：窗口概念激活，决定是否继续扫视
  └─ 终止：置信度达标 / 预算用尽 → 融合全局概念
```

## 4. 窗口编码器设计

### 4.1 感受器改造（核心）
`MultimodalExtractor.image()` 从"全图统计"改为"窗口统计"：

```python
def image_window(path, center, radius):
    """提取以 center 为中心、radius 半径的窗口局部特征。
    复用现有统计（颜色均值/亮度/edge/round），但只在窗口内计算。
    """
    # 窗口 = 以 center 为中心，radius 半径的圆形/方形区域
    # 窗口内特征 = 同现有 image() 的统计，但局限在窗口像素
```

### 4.2 窗口参数（大小自适应）
- **窗口中心**：由注意力控制器给出（可学习坐标）
- **窗口半径**：**自适应，多尺度池选择**（非连续调焦）
- **窗口特征维度**：与现有 VISUAL_FEATURES 对齐（9-10 维），但**含义是局部**

**窗口大小自适应 = 尺度空间 + 注意力控制器选尺度**：

```
预定义尺度池：{大窗口, 中窗口, 小窗口}   ← 固定 3-4 档，非连续
       ↓
注意力控制器用 winner-take-all 选一档（SNN 强项：离散选择）
       ↓
当前窗口 = 所选尺度 × 当前焦点位置
```

**为什么选尺度而非调连续值**：SNN 擅长离散选择（竞争胜出），连续回归是弱项。
3-4 档尺度已覆盖"远看轮廓/近看细节"，不需要连续。

**尺度决策信号**（SNN 内部可读，无需外部监督）：

| 信号 | 逻辑 | 对应 |
|------|------|------|
| 信息密度 | 窗口内特征方差大（细节多）→ 缩小；方差小（均匀）→ 放大找结构 | 显著性图峰宽度 |
| 置信度 | SNN 判断置信度低 → 缩小看细节；高 → 放大确认上下文 | 不确定性驱动 |
| 显著性峰值 | 峰越尖 → 越小窗口；越平 → 越大窗口 | 视觉显著度 |

这三个都能从 SNN 内部状态读出（膜电位方差/输出置信度/激活强度）——**自组织，无监督**。

### 4.3 局部 vs 全局信息
窗口丢失全局信息（看碎片不见全貌）——由**路径融合**补偿：
- 扫视路径的序列记忆（LIF 神经元膜电位残留 = 前窗口记忆）
- 多窗口概念加权融合（全局概念 = Σ 窗口概念 × 窗口显著性权重）

## 5. 视觉 SNN 改造（逐窗口脉冲）

### 5.1 输入层
现有：全图 9 维特征一次注入。
改造：**逐窗口注入**——时间步 t 注入窗口 W_t 的特征。

```python
# 现状（全图一次）
encode(feats): inject_input(fidx, fval) 全部特征一次注入

# 改造（逐窗口）
encode_windowed(windows): 
    for t, w in enumerate(windows):
        inject_input(w.features)   # 时间步 t 注入窗口 W_t
        snn.step()                 # 脉冲传播
        record_window_activation(t)
```

### 5.2 时间编码 = 扫视顺序
- 时间步 t0 → 窗口 W0 概念激活
- 时间步 t1 → 窗口 W1 概念激活
- ...
- **注意力焦点 = 特定时间步的放电模式**

### 5.3 概念检测层
现有 AND 门（阈值 1.0）+ 先验重叠问题（bright 连 4 概念）在窗口化后**需重新设计**：
- 窗口局部特征更有区分度（局部 edge/round 比全局更敏感）
- 概念检测层用**连续权重**（特征值×权重积分）替代布尔先验——这是之前记忆里"改造先验机制为连续权重"的方向

## 6. 并串混合 = 通感基础

用户洞察："视觉输入时应该同时可以有其他感官输入输出。并串混合应该是通感的基础。"

### 6.1 并行（多感官同时接收）
```
视觉 encode(visual) ─┐
听觉 encode(audio)  ─┼→ 并行，各模态独立编码
文本 encode(text)   ─┘
       ↓
ConceptRegistry：同概念跨模态注册（visual/audio/text → 同一概念维度）
```
已有基础：`multimodal_dataset` 已验证"苹果/危险跨模态激活同一概念"。

### 6.2 串行（注意力逐感官聚焦）
```
注意力控制器调度：先看（视觉聚焦）→ 再听（听觉聚焦）→ 结合（跨模态绑定）
```
扫视策略从"视觉窗口间"扩展到"感官间"。

### 6.3 通感 = 跨模态绑定
- 视觉"火" → 听觉"噼啪声"预期
- 概念节点跨模态共享（ConceptRegistry 已支持）
- **并串混合**：并行接收（多感官同时激活各自概念）+ 串行聚焦（注意力逐感官调度）
  = 通感的动力学基础

## 7. 训练难点（用户已意识到）

1. **扫视策略冷启动**：看哪里？无先验乱扫。需引导（弱监督：先看显著性高的区域）。
2. **局部 vs 全局**：窗口丢全局信息。需序列记忆（LIF 天然）+ 路径融合补偿。
3. **跨模态对齐**：哪感官输入对应哪概念？需对比学习（multimodal_dataset 对比正负对已有）。
4. **奖励稀疏**：扫视路径好坏的奖励信号难定。需塑形信号（高显著性窗口放电加强）。

## 10. 开放问题（待探索，不急于定）

> 2026-11-28 补充：5 个开放问题的务实判断（规模小、构造在摸索、不急于证明）

**核心原则：一次验证一个假设，别叠加。**

### 1. 窗口数量/扫视路径长度 —— 宁可少，别贪多
**判断：2-4 个窗口，扫视路径 3-5 步。**
- LIF 膜电位衰减 0.95/步，5 步衰减到 ~0.77——路径太长信息自我淹没
- 人眼实际扫视也是 2-5 次聚焦（不是无限扫）
- 当前 SNN 传播深度 5 步是设计上限，窗口超过传播深度就是浪费
- **别贪多**：规模小先用 2-3 窗口验证"SNN 能不能扫视"，成了再扩大

### 2. 显著性函数 —— 不定义，让 SNN 自己学
**判断：显著性 = SNN 对窗口的响应强度（自组织），不是预定义特征公式。**
- 最符合"SNN 自主建立"精神——不是人设计"什么值得看"，而是 SNN 对窗口的激活强度决定
- 人为定义显著性（边缘密度/对比度）就又回到人工编码，违背自主意图
- 现有 multimodal_features 的 edge/round/bright 是**特征**不是**显著性**；显著性应为**下游判断**（窗口概念激活强=值得聚焦）
- **显著性不是一个函数，是 SNN 的响应**

### 3. 扫视策略训练 —— 发育式探索-利用，不用强化学习
**判断：发育式（探索-利用平衡）+ 内在动机，不用 RL。**
- RL 奖励稀疏、训练不稳定——规模小会引入大量不确定性
- 发育式"先增殖探索、后竞争收敛"**已有**（development.py），直接复用到扫视策略
- 内在动机：窗口概念激活强度作为内在奖励（shaping）——不是外部奖励，是"SNN 自己觉得有意思"
- 弱监督引导（先看高响应区域）比外部 RL 奖励更稳
- **关键：不用 RL，用内在动机**——SNN 自己探索、自己觉得哪有意思就聚焦

### 4. 连续权重先验 —— 独立改进，别和窗口化耦合
**判断：窗口化先跑通，连续权重是后续独立改进。**
- 之前记忆明确："SNN 蒸馏恒 4% 是机制性：布尔先验无法表达连续阈值"——真问题
- **但**窗口化 + 连续权重是两个变量一起改，**无法归因**（失败不知道怪谁）
- 窗口化先用规则教师（区间判别）兜底，验证"SNN 能不能扫视"后，**再单独**改连续权重
- **别两个一起改**，一次只验证一个假设

### 5. VISUAL_FEATURES 维度 —— 内容与位置分离
**判断：窗口内容特征（9-10 维）进视觉 SNN 判概念；窗口位置/尺度进注意力控制器。两者不混。**
- 窗口**内容**（red/bright/edge/round...）决定"这是什么"→ 进视觉 SNN
- 窗口**位置**（center_x/center_y）+ **尺度**决定"接下来看哪"→ 进注意力控制器
- **位置不决定概念**（图标放大镜在左上还是右下都是 query）——位置混进判别层是错的
- **概念判别用内容，注意力调度用位置/尺度**。别把空间坐标塞进特征向量（那是 CNN 的错）

---

**务实路线（别一次做全）**：

```
窗口化（小规模 2-3 窗口）→ 验证"SNN 能不能扫视"（不急于证明）
  ↓ 成了
连续权重先验（独立改进，替换布尔）
  ↓
多感官并行 → 串行绑定（通感）
```

**核心原则**：一次验证一个假设（窗口化 → 连续权重 → 多感官），别叠加。SNN 规模小，贪多会什么都学不会。
